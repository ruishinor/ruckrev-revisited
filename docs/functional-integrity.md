# Functional integrity and continuity

Baseline: PR #27, 5f2311c1579544f57618fc2ead268af74e22ec13. No asset, catalogue, dependency, security header or workflow changes.

- Workspace schema v2 reads v1 documents and backups without inventing targets or associations. The revision is preserved; migration is in memory until an explicit save. The IndexedDB database version also advances to 2 without recreating its store: old connections are closed by the version-change handler and old applications cannot reopen version 1. V2 backups need the updated application. Keep a v1 backup before upgrading if rollback is necessary; reload old tabs before editing. A rollback to the old application will not open the upgraded database. New record types are versioned self-reported challenge attempts, not certificates. Existing achievements are not relabelled.
- Programme preparation retains its initial personal target date, optional active goal ID and event reference alongside the original programme reference. Goal changes trigger a visible review warning; no silent calendar changes. Missing historical links remain recoverable. New incorrect relationships between existing records are rejected transactionally. Old malformed relationships can still be exported and repaired; missing targets are not automatically deleted.
- Editing skipped or replaced planned sessions preserves their status. Explicit restoration is available for skipped sessions. Closing a programme can retain all scheduled sessions or explicitly mark outstanding sessions dated today or later as skipped. No completed or past history is removed.
- The shortlist uses actual structured schedule length, objective pathway, experience, first-week repeatable duration, weekly time, days, and limited equipment/terrain exclusions. It is not a coaching decision. Missing machine-readable prerequisites are presented for manual review. The general block generator retains its conservative rules.
- Activity totals are separate; matched assessment benchmark changes require identical user-stated activity name, assessment, unit and conditions and different dates. They are not official score equivalence, verified protocol compliance or readiness predictions.
- The contribution page provides a manual email path to the existing public contact address under the owner's authorization. Drafts stay local until the sender chooses to email. No mail is sent automatically, no public submissions or backend are added, and mailbox delivery/retention arrangements are not independently verified. Review attachments, consent, and privacy before publication.
- Privacy copy explicitly distinguishes persistent browser data from server-side data and links directly to export and deletion controls. Controller identity, provider retention, mailbox operations and legal compliance still need operator verification.

Remaining: actual-device usability and accessibility, individual source and copyright review, verified historical captures, programme-specific practitioner review, a governed editorial review/retention process and longitudinal leadership practice. Benchmark comparison is based on user-declared conditions; protocol-level component IDs and historical source revisions are not yet modelled.
