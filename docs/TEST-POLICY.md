# Risk-based verification policy and initial pruning

Baseline PR #34: 156 unit tests and 82 browser tests passed. Unit suite took approximately one second; browser suite 49 seconds locally, hosted browser job 1m37s. The problem is not primarily test count or runtime; it is maintenance friction, false quality assurance and repeated full preflight for mistakes that could be caught by targeted tests. Preserve required CI and security checks. This package does not change workflows, dependencies, branch rules, production code or CSP.

## Decision rule

Keep a test if it protects an observable user journey, a defined factual contract, a security/data integrity invariant, a previous real regression, or a release invariant. Remove/consolidate assertions that only protect an incidental implementation detail, current catalogue size, wording length, arbitrary historical layout, or a fully duplicated check. Prefer domain contracts over DOM strings; prefer one meaningful browser test per integration path, with cheap catalogue-wide static checks. Do not set a target number of tests to delete. Tests that catch actual behaviour problems are not arbitrary because they fail.

## Binding owner rule — copy is not a release gate

Ordinary copy edits must not be blocked by automated tests. No hard-coded public sentences, headlines, CTA labels, marketing slogans, paragraph text, forbidden-word lists, prose snapshots, narrative checksums or exact copy matching. This applies equally to legal and safety wording: editorial review owns meaning and accuracy; automation checks the presence and operation of relevant controls, destinations and required data. Preserve source attribution and original narratives by editorial/source review, not by locking their prose in CI. Use stable IDs, roles, links, structured values and data-derived expectations rather than literal wording. Accessible names must remain meaningful, but their exact phrasing is not a contract. A change to a factual threshold, unit, official protocol, data format, record semantics or security behavior is not a copy-only change and remains testable. Comparing generated exports with their current data source tests fidelity, not a frozen copy snapshot. Never skip CI to make a copy edit pass; repair the test's coupling instead.

A reviewed intentional removal must update that preservation list along with redirects/migration and a rationale. New routes need no snapshot update unless explicitly promoted to the preservation baseline. This is stronger than a hard-coded count that can pass after replacing useful entries.
- Remove minimum word quotas and fixed step counts from individual field-guide tests; preserve schema coverage, nonempty distinct instructions, rendering, download/record and version semantics. Human review assesses substance. Current two target options remain a real shared renderer contract until redesigned.
- Remove duplicate challenge-photo unit tests in brand-correction and roadmap-23; consolidate into roadmap-22 retaining every challenge mapping, distinct bytes, JPEG signatures, original logo, safe SVG and generated disclosure. Keep user-approved brand mark and glyph hash contracts and actual responsive decoding.
- Remove redundant all-challenge desktop browser visit loop; keep all 25 mobile visits (real prior overflow regression) and check structural sections/record controls to that loop. Static route render checks still cover every page. Keep library filter and mobile navigation journey; use live catalogue sizes. No `overflow:hidden` workaround or weaker width threshold.
- Remove arbitrary fixed guide block/bullet counts for crew guide structures, retain valid sections and unique drill IDs; derive drill selection expected size from eligible records. Keep exact chosen programme schedule lengths, exercise protocol numbers, safety constraints and specific facts where deliberate.
- Remove both inspected public-copy blacklist tests, including “evidence” and “mission-ready”; voice remains an editorial standard. Remove inspected marketing, legal and field-report prose assertions and narrative checksums, and use stable challenge structure and record controls instead of exact headings. This is a bounded first pruning pass, not an exhaustive refactor of all 39 unit files and 14 browser specs. Some incremental fixture counts, copy-dependent locators/assertions in other suites, and redundant checks remain; Q04 is an immediate follow-up, not permission to add new copy gates. Do not delete tests blindly by regex. Exact anchors in the patch refuse drift. ## Keep unchanged

- Unit validation of calculations, source-specific standards and scope, variant semantics, unknowns, explicit outcome, import/backup/migration, stale writes, corruption, CSV injection, unsafe inputs, no false overall pass, GPX bounds, comparison selection, dates, versioning.
- Build all routes; reject broken local links/assets, duplicate/unsafe paths, tracked dist and invalid photo mappings/reuse. Generated assets must be locally present. Do not call graphic coverage photographic coverage. Maintain photo licence/source records via human review.
- Browser journeys: search/filter/reset, URL/state restoration, early input, comparison, keyboard focus, mobile navigation, challenge layout, image decoding, downloads, actual workspace transactions, stale tabs, data restore, explicit save and export, programme import, crew continuity, local GPX/no external requests, local HTTP policy. Retain exact prior real regression tests.
- Node 22 and pinned matching Playwright runner/container, immutable actions, required `check` and `browser`, branch protections and exact head validation. No forced merges, disabled retries policy, skipped CI or weaker security.

## Release workflow

Read current main SHA and open PRs. Use isolated worktree, check clean, scope exact staged paths, validate changed source and generated mapping as one transaction. On failure inspect first actionable error and fix root cause; retain candidate. No repeat acquisition or fresh clone if already available. Local full verify and browser once. Publish exact SHA, require actual registered CI and Vercel checks, merge only mergeable tested head. Verify main CI and production deployment alias separately. Capture a concise record of changed user-visible pages and blockers. Never equate a green pipeline with editorial acceptance.
