# My Training

## Ownership and boundaries

P1 introduces a device-local personal workspace, using the existing static application and generated training block. It does not create accounts, sync, analytics, a server API, or an external data store. The site and its scripts must first be loaded; offline reload and service-worker caching are not implemented. Browser data is not a permanent backup and is not encrypted separately from the browser profile.

IndexedDB was selected over localStorage for transactional compare-and-write, asynchronous access, and multiple-tab conflict prevention. The data volume is deliberately limited to 10,000 records and 2 MB of encoded JSON. A single document is read and written in one transaction, which favors straightforward validation and atomic changes over incremental query optimization at this scale. Schema version 1 is the initial format; unsupported versions are rejected, not guessed. Future changes must implement explicit migration in `migrate` and test old backups. Storage failures are reported; no save is acknowledged until the write transaction commits. Explicit deletion clears personal records and advances the revision. A corrupt record can be reset with explicit confirmation; no automatic reset occurs. Downloads are not deleted by the workspace.

## Data contract

`{schemaVersion:1,revision,records:[...]}`. Every record has `id`, `kind`, local ISO calendar `date`, `title`, `notes`, and a nullable `ref` containing `kind`, `id`, and display `label`. The catalogue is authoritative for links, and unresolved references are displayed as unavailable. Imported strings are never used as link destinations. P2/P3/P5 should use stable catalogue keys: guide `path`, assessment `id`, challenge `path` (when present), checklist `id`; do not store full content. If a later catalogue replaces a path with an opaque ID, provide a deliberate resolver alias or migration. There is no current cross-workstream contract agreement; this is the proposed compatibility adapter based on inspected code.

Session and plan share optional numeric measurements (null is missing; zero is recorded zero) and required activity. Completed sessions require duration; planned sessions do not. A completion points to its plan by ID; a plan is completed only if a corresponding actual record exists. Deleting either does not silently cascade. Programmes own their generated sessions through `programmeId`; closing a programme retains its schedule and history. Replacement explicitly marks the original plan replaced and creates a new plan. Missing links are permitted to retain history. A record of a milestone is self-recorded or user-declared documented, never independently certified. Benchmarks require a unit and conditions. No readiness or physiological score is generated.

The programme recommendation uses available time, days, repeatable duration, experience, objective, equipment, terrain and return status. The existing `buildProgression` supplies the schedule; zero automatic increases, familiar load, spaced training days, optional fourth day left free. Selecting a catalogue article associates it as reading rather than importing its actual sessions; P3 must expose structured schedule metadata for exact programme-to-calendar mapping. No automatic catch-up or silent workload increase. Users review overlaps before adding another block.

## Portability and security

JSON imports are bounded, explicitly validated, previewed, and merged in a single transaction. Exact ID/content duplicates are skipped; conflicts reject the entire import. Distinct IDs are not treated as duplicates merely because activity/date match. Unknown fields and unsupported schema versions are rejected. CSV quotes cells and prefixes dangerous spreadsheet formula-leading text; CSV export is for analysis, JSON for restoration. User input is rendered with textContent; links resolve through trusted existing catalogue entries. No new external dependencies, URLs from personal records, or security-header changes. Full offline application support, automatic backups, cross-device sync, cryptographic result verification and arbitrary file attachments are intentionally absent.
