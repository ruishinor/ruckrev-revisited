# Repository maintenance

Baseline: `58db0fc4d0c211212023351cc9919cd0bb034510` (PR #24).

## Source and build output

`dist/` is generated by `npm run build`; never commit it. The existing history is not rewritten. GitHub Pages is disabled and Vercel builds from source. `scripts/route-inventory.mjs` owns the route and template inventory for build and validation. Tests check the pre-existing route coverage and reject duplicates. The publication wrapper builds both the baseline and the candidate and compares SHA-256 manifests of every generated file. A mismatch stops publication. `vercel.json` is the authoritative global header policy; the local development server consumes the same config for every response, while retaining local `Cache-Control: no-store`. Browser tests exercise actual local HTTP responses. This is not a claim that Vercel's edge headers were independently inspected.

## Dependency changes

- Dependabot proposes GitHub Actions updates only, once per week. Review official release notes and tag-to-full-SHA mapping, action runtime, runner/container compatibility and signed commit when available. Keep the existing jobs, Node 22, read-only permissions and no credential persistence. Review both occurrences of each action pin; no automatic merges.
- Playwright is deliberately excluded from standalone Dependabot npm updates. Select a stable release and check the upstream release notes and the Microsoft Container Registry image for the matching `-noble-amd64` tag. Resolve the actual manifest digest for linux/amd64 with `docker buildx imagetools inspect mcr.microsoft.com/playwright:v<VERSION>-noble-amd64` on a Docker-capable machine, or equivalent registry inspection. Do not copy an unrelated digest or use a floating tag.
- In one PR, change the exact `@playwright/test` version in package.json, regenerate the lockfile with `npm install --package-lock-only --ignore-scripts --no-audit --no-fund`, and update the matching workflow image tag and verified digest. Review the lockfile diff and `npm audit` separately; do not use `npm audit fix --force`. Run `npm ci --include=dev --ignore-scripts --no-audit --no-fund`, `npm run verify`, local Chromium preflight and the full suite. Hosted pinned-container Chromium launch and full browser suite must pass. No bypass of flaky-test rejection. Keep the Node 22 application test baseline. Vercel installs only production dependencies.
- To release, require the exact candidate's hosted `check` and `browser` jobs and all PR checks, merge, then verify post-merge CI and production alias. Do not weaken required checks to unblock an update.

## Ruleset

Existing `shield-5` should remain active with no force pushes or branch deletion. The authenticated publication wrapper can add mandatory PRs and strict `check`/`browser` status checks, tied to the observed GitHub Actions app ID 15368. It backs up the current rules, refuses unexpected changes and reads the new settings back. Zero review approvals avoids locking a solo maintainer out. Vercel checks remain required by the publication wrapper; a production deployment itself cannot be required before merging. No administrative bypass is introduced. If the API refuses the settings change, do not disable protection; inspect the repository's settings and permissions.

Further splitting of application modules is deferred to focused, behaviour-tested changes. File size alone is not a reason to introduce abstractions or change the architecture.
